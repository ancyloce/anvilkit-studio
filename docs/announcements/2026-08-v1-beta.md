# Announcing AnvilKit Studio v1.0.0-beta

**Today we're tagging `v1.0.0-beta.0` across the AnvilKit Studio runtime
cone, the first-party plugins, and the shared UI package.** If you've
been following along on the `0.1.0-alpha.x` line, this is the release
where the public API gets pinned. Beta means the shapes are stable —
anything that changes between now and `1.0.0` stable goes through the
documented semver process.

> **Status:** draft. Post needs maintainer sign-off before publishing
> externally (dev.to, blog, socials). Tracking: `phase4-018`.

## What's in the beta

- **`@anvilkit/core@1.0.0-beta.0`** — the `<Studio>` React shell,
  `StudioConfigSchema` (Zod-validated), `compilePlugins`, the
  `StudioPlugin` contract, and the `StudioError` family. Entry-chunk
  budget: **25 KB gzipped**, enforced in CI.
- **`@anvilkit/ir`, `@anvilkit/schema`, `@anvilkit/validator`
  @ `1.0.0-beta.0`** — the headless pipeline. Round-trip Page IR,
  AI-context derivation from Puck configs, and a validator that now
  closes three gaps flagged by our phase4-014 security review.
- **`@anvilkit/plugin-export-html@1.0.0-beta.0`** — the first real
  HTML exporter, backed by a 24-test XSS / URL / CSS-injection
  hostile-input battery.
- **`@anvilkit/plugin-ai-copilot@1.0.0-beta.0`** — a headless AI
  copilot plugin with a `./mock` subpath for CI harnesses and
  structured `ai-copilot:error` events.
- **`create-anvilkit-plugin`** — a standalone scaffolder for
  `@anvilkit/*` StudioPlugin packages. Generates a buildable
  skeleton wired to `@anvilkit/core/testing`.
- **[docs.anvilkit.dev](https://anvilkit.dev)** — a Starlight docs
  site with a generated component catalog, TypeDoc API reference,
  guides, and an interactive Puck playground.
- **`@anvilkit/ui@1.0.0-beta.0`** — first public npm publish of the
  shared UI primitives.

## Install

```bash
pnpm add \
  @anvilkit/core@beta \
  @anvilkit/ir@beta \
  @anvilkit/schema@beta \
  @anvilkit/validator@beta \
  @anvilkit/plugin-export-html@beta \
  @anvilkit/plugin-ai-copilot@beta
```

Or pin to the `1.0.0-beta` range directly:

```bash
pnpm add @anvilkit/core@^1.0.0-beta
```

## Upgrading from `0.1.0-alpha.x`

The [migration guide](../migration/0.x-to-1.0-beta.md) enumerates
every breaking change, package-by-package, with before/after snippets.
The short version:

- **Three validator behaviour changes.** `validateAiOutput` now
  rejects `root.type !== "__root__"`, non-array `root.children`, and
  non-JSON-serialisable `props`. Adapters that produced any of those
  shapes will surface structured `VALIDATION_FAILED` events instead
  of crashing downstream.
- **`@anvilkit/core/testing`** is new but non-breaking — recommended
  for any plugin test suite.
- **Component packages stay on their `0.0.x` cadence.** Only the
  runtime cone bumps to `1.0.0-beta`; a component at `0.0.3` remains
  compatible with `@anvilkit/core@^1.0.0-beta`.

## What "beta" means for AnvilKit Studio

- **API shapes are pinned.** Between `1.0.0-beta.N` and `1.0.0-beta.N+1`
  we do not remove or rename public exports. We can still tighten
  validators or fix bugs whose previous behaviour was a contract
  violation — those are called out in the per-beta changelog.
- **We're actively looking for feedback.** That's the point of beta.
  Please file issues against the
  [repo](https://github.com/ancyloce/anvilkit-studio/issues) with the
  `beta-feedback` label. See
  [`docs/beta-feedback/README.md`](../beta-feedback/README.md) for the
  triage policy and what kinds of reports help most.
- **Security findings go through `docs/security/plugin-trust-model.md` §8.**
  Do not open public issues for those.

## What's next

- A tick-over of internal integrations and example apps to `1.0.0-beta`
  to surface real-world pain before stable.
- A second beta (`1.0.0-beta.1`) folding in early feedback.
- `1.0.0` stable once the feedback window closes and the known-issues
  tracker is empty.
