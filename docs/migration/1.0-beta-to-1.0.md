# `1.0.0-beta.0` → `1.0.0` migration

**Status:** **Planned — not yet shipped.** Neither `v1.0.0-beta.0` nor
`v1.0.0` has been tagged.
**Last refreshed:** 2026-08-04 (versions, paths, and CLI surface
re-verified against the tree).
**Target audience:** host apps upgrading from
`@anvilkit/*@1.0.0-beta.x` to `@anvilkit/*@1.0.0` stable.

> **Version reality check.** The runtime cone ships **`0.1.18`** today and
> `packages/runtime/core/CHANGELOG.md` has no `1.x` entry, so *both* ends of
> this migration are still hypothetical. This is the **exit-beta runbook**,
> not a record of a release. See
> [`0.x-to-1.0-beta.md`](./0.x-to-1.0-beta.md) for the same caveat on the
> preceding step.
>
> One part did ship independently: the **10 first-party template packages**
> in §2 are real and are on `1.0.2` today under
> `packages/extensions/templates/` — templates version on their own line,
> not with the runtime cone.

`v1.0.0` exits the beta pre-release channel. Nothing in the public
API surface changes in a breaking way between the final
`1.0.0-beta` and `1.0.0` — this document is primarily a summary of
what moved during beta, a short runbook for the exit, and a pointer
to the LTS policy that takes effect on the `1.0.0` tag.

**No code changes are required to upgrade.** The version range bump
from `^1.0.0-beta.0` to `^1.0.0` in your `package.json` is enough.

pnpm add \
  @anvilkit/core@^1.0.0 \
  @anvilkit/ir@^1.0.0 \

## 2. What moved during beta

### Additive

- **`@anvilkit/core/templates` subpath.** New type-only surface
  shipping the `AnvilkitTemplate`, `AnvilkitTemplateManifest`,
  `AnvilkitTemplatePreview`, `AnvilkitTemplatePackage` types plus
  the `isAnvilkitTemplate()` structural guard. Zero impact on the
  main `@anvilkit/core` bundle — see `phase5-016` and the decision
  record, now archived at
  `docs/archive/decisions/003-core-templates-subpath.md`. The subpath
  is live today (`@anvilkit/core/templates`).
- **10 first-party `@anvilkit/template-<slug>` packages** shipped
  under the `latest` dist-tag on `1.0.0` (`phase5-017`). Seed list:
  `landing-saas`, `landing-agency`, `landing-docs`,
  `pricing-comparison`, `blog-index`, `blog-article`,
  `feature-overview`, `contact`, `about`, `changelog`.
- **`anvilkit` CLI — `@anvilkit/cli` (`phase5-005`).** First GA release
  planned for `1.0.0`. The shipped command set is `init`, `validate`,
  `add`, `export`, and `generate`
  (`packages/tooling/cli/src/commands/`). The `doctor` subcommand named
  in the original draft was never implemented; `add` (see
  [`1.0-to-1.1.md`](./1.0-to-1.1.md) § 2.3), `export`, and `generate`
  landed instead.
- **`anvilkit init --template <slug>`** reads from the 10 seed
  templates and scaffolds a ready-to-run project.
- **`@anvilkit/plugin-export-react`.** First public GA. Generates a
  Next.js-flavored React export from a `PageIR`.
- **`@anvilkit/plugin-version-history`.** Snapshots + restores
  editor state across sessions.
- **`@anvilkit/plugin-asset-manager`.** Browses and uploads shared
  assets from a configurable backend.

### Behavioral fixes (non-breaking)

- **Validator F-2** (`[INVALID_CHILDREN]`, `phase4-014`). A non-
  array `children` was previously accepted and crashed downstream
  at `irToPuckPatch`. `validateAiOutput()` now rejects it with an
  explicit error. **If you were already feeding valid IR to the
  validator, nothing changes.** If you were feeding malformed IR,
  errors are now caught at validation time instead of crashing
  later.
- **Validator F-3** (`[NON_SERIALIZABLE_PROP]`, `phase4-014`). The
  validator now recursively rejects props containing functions,
  symbols, bigints, or cyclic graphs. Previously these slipped past
  and broke `structuredClone` + `localStorage` rehydration.

No public type narrowed in either fix; both ship as additive error
cases in `AiValidationResult.issues`.

### Docs site

- Templates catalog went live (`phase5-018`). It now lives as a docs
  content section at `apps/docs/content/docs/templates`, with the
  filterable catalog served by the `apps/docs/src/routes/marketplace.tsx`
  route.
- Homepage banner flip from "Beta" to "1.0 GA" — **not done**, and
  correctly so: the GA cut never happened, and the root `README.md`
  still states the project is in pre-1.0 beta.
- `docs/policies/lts.md` added; linked from the root README. ✔ done.

> The docs app was rebuilt on Fumadocs + TanStack Start after this
> section was written; it is no longer an Astro site, so any
> `apps/docs/src/pages/*.astro` path in an older draft is dead.

## 3. Exit-beta runbook

For the release lead only. Consumers do not run any of these steps.
The standalone `docs/release/release-runbook.md` referenced in earlier
drafts was never written; the executable source of truth is
`.github/workflows/publish.yml`, whose `mode` input implements the
`enter-beta` / `exit-beta` ceremonies described below.

1. Land all queued changesets. `pnpm changeset status --verbose` to
   confirm only expected bumps will go out.
2. Trigger the `Publish` workflow with `mode=exit-beta` via
   `workflow_dispatch`. This runs
   `pnpm changeset pre exit` and pushes the commit.
3. Merge the auto-opened "Version packages" PR, which drops every
   `fixed`-group package to `1.0.0`.
4. Confirm the `Publish` workflow publishes under the `latest`
   dist-tag, not `beta`.
5. Tag the release: `git tag v1.0.0 && git push --tags`.
6. Announce via the GA announcement draft, now archived at
   `docs/archive/announcements/2027-03-v1-ga.md`.

The `phase5-019 phase4-017` automation handles steps 2 and 4 end-
to-end; the only manual steps are (1) the changeset triage, (3) the
PR merge, and (6) the announcement.

## 4. Breaking changes

**None.** If a consumer hits a behavioral change not listed in §2,
it is a regression — please file an issue. The 12-month patch
window on `v1.0.x` (see `docs/policies/lts.md`) covers regressions
from `v1.0.0` onward.

## 5. Deprecations carried forward

No exports were deprecated during beta. The deprecation window
defined in `docs/policies/lts.md` starts from `v1.0.0` — any
`@deprecated` marker added in a post-GA minor must remain callable
for at least 2 subsequent minors (~6 months) before removal.
