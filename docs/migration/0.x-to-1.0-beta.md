# 0.x → 1.0.0-beta.0 migration

**Status:** draft, pre-`v1.0.0-beta.0` (`phase4-017`).
**Target audience:** host apps upgrading from an `@anvilkit/core@0.1.0-alpha.x`
or `@anvilkit/plugin-*@0.1.0-alpha.x` install.

Beta pins the public API. Anything in this document is a concrete
migration step or a semver-breaking behaviour change that shipped
between `0.1.0-alpha.0` and `1.0.0-beta.0`. Non-breaking additions
(new fixtures, bench harness, bundle-size gates, etc.) are listed
in "Also landed" at the end and do not require code changes.

## Package-by-package

### `@anvilkit/core`

| From        | To               | Notes |
| ----------- | ---------------- | ----- |
| `0.1.0-alpha.x` | `1.0.0-beta.0` | First `beta` tag. Subpath exports stable. |

- **New subpath export `@anvilkit/core/testing`.** Non-breaking — see the
  plugin authoring guide §7 for the fixtures.
- `StudioPluginContext` is now the canonical context shape. If you
  built a plugin against the `alpha.0` shape, `compilePlugins()`
  still accepts it; nothing moved in the public field set.
- The `<Studio>` entry-chunk budget remains 25 KB gzipped
  (enforced by `check:bundle-budget`) and full-index budget is 75 KB
  gzipped (enforced by `size-limit`, phase4-016).

### `@anvilkit/ir`

| From        | To               | Notes |
| ----------- | ---------------- | ----- |
| `0.1.0-alpha.x` | `1.0.0-beta.0` | No breaking changes in the transforms. |

- `puckDataToIR(data, config, opts?)` signature is stable; `config`
  is required.
- `irToPuckData(ir)` is stable.
- Canonicalisation behaviour unchanged (identifier stability +
  sorted props).

### `@anvilkit/schema`

| From        | To               | Notes |
| ----------- | ---------------- | ----- |
| `0.1.0-alpha.x` | `1.0.0-beta.0` | No breaking changes. |

- `configToAiContext(puckConfig)` output shape is
  `{ availableComponents: AiComponentSchema[] }`. Each
  `AiComponentSchema` carries `componentName`, `description`, and
  `fields[].fieldName / description / type`.

### `@anvilkit/validator`

| From        | To               | Notes |
| ----------- | ---------------- | ----- |
| `0.1.0-alpha.x` | `1.0.0-beta.0` | Three validator gaps closed (phase4-014 F-1/F-2/F-3). |

Breaking **behaviour** changes (not API changes) resulting from the
phase4-014 security review. Each is covered by a flipped pin test
in `plugin-ai-copilot/src/__tests__/security.test.ts`:

1. `validateAiOutput` now rejects `root.type !== "__root__"` with
   `[INVALID_ROOT_TYPE]`. Any AI adapter producing a non-`__root__`
   root must be updated to emit `root.type: "__root__"`. (Fixes
   **F-1**.)
2. `validateAiOutput` now rejects a non-array `root.children` with
   `[INVALID_CHILDREN]`. Previously the plugin crashed with
   `.map is not a function` out of `runGeneration()`; now the
   plugin cleanly emits `VALIDATION_FAILED` on the event bus. No
   adapter change required unless the adapter deliberately
   returned a non-array children value. (Fixes **F-2**.)
3. `validateAiOutput` now rejects non-JSON-serialisable `props`
   (functions, symbols, bigints, recursively) with
   `[NON_SERIALIZABLE_PROP]`. Adapters that returned a function in
   a prop bag (e.g. inline `onClick` handlers) start failing with
   `VALIDATION_FAILED`. The walker is cycle-safe and
   depth-bounded at `MAX_DEPTH` to match the node-walk budget.
   This was always a violation of the IR contract; beta enforces
   it. (Fixes **F-3**.)

## Before / after snippets

### AI copilot: structured error handling

Previously, a non-array `children` could throw out of
`runGeneration()`. Host code that wrapped the call in a try/catch
saw a `TypeError`.

```ts
// before — bare-catching hides structure
try {
	await plugin.runGeneration(prompt);
} catch (err) {
	toast("Something went wrong");
}
```

With F-2 closed, the plugin now emits a typed event instead.
Consume it:

```ts
// after — structured, typed, logged
ctx.on("ai-copilot:error", (payload) => {
	if (payload.code === "VALIDATION_FAILED") {
		toast("Generation rejected: " + (payload.issues?.[0]?.message ?? "bad IR"));
	}
});
await plugin.runGeneration(prompt);
```

### Plugin tests: prefer `@anvilkit/core/testing`

Before:

```ts
function makeCtx(): StudioPluginContext {
	return {
		getData: () => ({ root: { props: {} }, content: [], zones: {} }),
		getPuckApi: vi.fn() as unknown as StudioPluginContext["getPuckApi"],
		studioConfig: StudioConfigSchema.parse({}),
		log: vi.fn(),
		emit: vi.fn(),
	};
}
```

After:

```ts
import { createFakeStudioContext, registerPlugin } from "@anvilkit/core/testing";

const harness = await registerPlugin(myPlugin);
await harness.runInit();
expect(harness.ctx._mocks.logCalls[0]).toEqual(["info", "started", undefined]);
```

         @anvilkit/plugin-ai-copilot@beta
