# `@anvilkit/canvas-templates`

Forty starter [`CanvasIR`](../../../capabilities/canvas/core/src/ir/types.ts)
designs shipped with AnvilKit Canvas Studio — social posts, stories, reel and
TikTok covers, YouTube thumbnails, LinkedIn banners, slides, and print pieces.
Each one is a self-contained `CanvasIR` (text / rect / ellipse / polygon /
star / frame nodes only, **no external assets**) so it loads with zero network
calls and carries no third-party licence claim.

## Contract

`src/index.ts` exports a typed `canvasTemplates` registry (id →
`CanvasTemplateCatalogEntry`, the canonical `CanvasTemplateDefinition` plus a
`description`) and `canvasTemplateList`, plus the controlled tag vocabulary
(`CANVAS_TEMPLATE_TAG_AXES` / `CANVAS_TEMPLATE_TAGS`). Every `document` is
decoded through `migrateCanvasIR` and validated against both
`CanvasTemplateDefinitionSchema` and `validateCanvasIRInvariants` from
`@anvilkit/canvas-core` — enforced by `src/__tests__/canvas-templates.test.ts`.

```ts
import { canvasTemplateList, canvasTemplates } from "@anvilkit/canvas-templates";

const poster = canvasTemplates.poster.document; // CanvasIR
```

## What a template may use

The suite gates this, because a template that references an unimplemented
capability looks finished in JSON and blank on the canvas:

- **No animation.** `meta.animation` / `page.animation` is metadata only; it is
  never played and never exported.
- **No video or audio.** Contract-only node kinds — video renders a static
  poster at best, audio renders nothing.
- **No bundled imagery.** An image well is an EMPTY `frame` with an `image`
  placeholder and no `assetId`; the editor draws it as an "add an image"
  affordance. `document.assets` is `{}` in every template, so there is no
  SPDX/CC0 provenance to record and none to get wrong.
- **`Inter` only, for now.** Nothing in `@anvilkit/canvas-editor` injects a
  font catalog family's stylesheet for a *document* font — only the font
  picker's own option preview does — so any other family opens in a fallback
  face. Widen `TEMPLATE_FONT_FAMILIES` in the suite only alongside a real
  font-loading seam.
- **`solid` page backgrounds only.** `image`/`gradient` page backgrounds fall
  back to white on the stage and warn `BACKGROUND_UNSUPPORTED` on export; a
  gradient belongs on a full-bleed `rect` fill, which every renderer paints.

## Size presets

`CANVAS_SIZE_PRESETS` (`@anvilkit/canvas-core`) is deliberately social-only.
Each of its eight formats carries exactly three templates; the other sixteen
templates are print and presentation sizes and correctly declare no
`supportedSizes` at all. `sizePresets(...)` **throws** on an id that is not in
the catalog (cp0-003), so a typo is a module-load failure, not silence.

## Registry order is load-bearing

The Templates panel pages a static catalog at 20 entries and renders insertion
order. The original ten therefore stay first — that is what
`apps/studio/e2e/canvas/templates-panel.spec.ts` asserts is visible without
paging. **Append; do not interleave.**

## Layout

```
packages/extensions/templates/canvas/
├── package.json
├── tsconfig.json
├── vitest.config.ts
└── src/
    ├── index.ts                 # typed registry + tag vocabulary
    ├── *.json                   # one committed CanvasIR per template
    └── __tests__/
        └── canvas-templates.test.ts
```

The original ten `*.json` files were generated by
[`../scripts/scaffold-canvas-irs.mjs`](../scripts/scaffold-canvas-irs.mjs)
(`pnpm --filter @anvilkit/templates-workspace scaffold:canvas-irs`). **The
thirty added by `cp3-007` are hand-authored and are not in that script's
table** — it only writes the files it knows about, so re-running it is safe,
but it is no longer the source of truth for the catalog.

## Build

`tsc` copies the imported `*.json` into `dist/` (via `resolveJsonModule`),
matching the Puck `@anvilkit/template-*` packages alongside this folder.
The dir is skipped by `scripts/verify-templates.mjs` (which validates the
Puck `AnvilkitTemplate` packages) and validated by its own Vitest suite.
