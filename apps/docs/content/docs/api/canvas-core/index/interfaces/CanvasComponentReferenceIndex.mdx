Where every component is referenced FROM (plan 0023 M3-08, LC-DELETE):
page instances and Source-tree instances, keyed by the referenced
component id. The read `component.delete` guards on and "detach all and
delete" plans over. Entry order follows `walkDocument` — pages in
document order, then definitions in sorted id order — so messages and
plans built from it are byte-stable.
