---
title: Visual editor adoption
description: "Adopt the Puck-native authoring protocol: declare named style targets in metadata v2, stamp stable target attributes in your render, and carry appearance/interactions/bindings as ordinary component props."
---

The visual editor never guesses at your component's structure.
Everything it can do for your component comes from what you
**declare** — and since the Puck-native refactor (PLAN-0025), those
declarations live in exactly three places, all of them ordinary Puck
concepts:

1. **`metadata.anvilkit.editor` (v2)** — your component's named style
   targets and per-target property allowlists.
2. **Your render** — every declared target stamps its stable attribute
   pair in **every** mode (editing, preview, production, export).
3. **Your props** — authored state arrives as serializable component
   props (`appearance`, `interactions`, `bindings`) plus the shared
   hidden fields. There is no sidecar, no config decoration, and no
   editor-only render path.

A component that declares nothing is not broken — it keeps working
with native Puck fields. Adoption is opt-in and reversible.

## 1. Declare metadata v2

```ts
// src/config.ts
export const componentConfig = {
	fields: { /* your native Puck fields */ },
	metadata: {
		anvilkit: {
			editor: {
				version: "2",
				styleTargets: {
					root: {
						label: "Card",
						responsive: true,
						properties: ["display", "padding", "background", "opacity"],
					},
					media: { label: "Media", properties: ["opacity"] },
				},
			},
		},
	},
	render: CardView,
};
```

- `styleTargets` keys are part of your **data contract**: renaming a
  published target requires a prop migration.
- Grant only properties your DOM actually honors. The unified
  appearance compiler rejects everything else with a diagnostic — a
  granted-but-ineffective property is a bug the editor will surface.

## 2. Stamp the target attributes

```tsx
// src/CardView.tsx
import { anvilRootAttrs, anvilTargetAttrs } from "@anvilkit/core/editor";

export function CardView({ id, image, children }: CardProps) {
	return (
		<section {...anvilRootAttrs(id, "root")} className="ak-card">
			<img {...anvilTargetAttrs(id, "media")} src={image} alt="" />
			{children}
		</section>
	);
}
```

The pair (`data-ak-style-node` + `data-ak-style-target`) is the ONLY
selector surface the compiler emits against. Stamp it identically in
every render branch — the editing canvas, `<Render>`, and the
exporters must see the same boxes. A target that exists only in some
branches must be re-homed on a stable container.

## 3. Carry the authoring props

```ts
import {
	appearanceField,
	bindingsField,
	interactionsField,
} from "@anvilkit/core/react/editor";

export const fields = {
	...nativeFields,
	appearance: appearanceField(),
	interactions: interactionsField(),
	bindings: bindingsField(),
};
```

Authored state is now **data you own**: `props.appearance` holds
per-target layered styles (`base` + breakpoint overrides +
`styleRefs` + `hidden`), interactions ride their trigger node, and
bindings ride the node they bind. Document-level state (design
tokens, breakpoints, style definitions) lives in
`root.props.designSystem`. Everything is serializable; render props
never expose functions.

## 4. Prove it

Every adopted component ships two tests:

```ts
it("declares valid v2 metadata", () => {
	expect(readEditorMetadataV2(config, "Card")?.styleTargets.root).toBeDefined();
});

it("emits identical targets in editing and production", () => {
	const editing = renderToStaticMarkup(editingBranch);
	const production = renderToStaticMarkup(<Render config={config} data={doc} />);
	expect(targetPairsOf(editing)).toEqual(targetPairsOf(production));
});
```

The workspace harness in `packages/extensions/components/tests/`
enforces both for every bundled package — copy its pattern
(`authoring-contract.ts`, `authoring-parity.ts`) for new packages.

## Inline text targets

Elements holding inline-editable content stamp a text target and
declare it in metadata (`inlineText`):

```tsx
<h1 data-ak-text-target="headline">{props.headline}</h1>
```

Always pair an image's `src` with its `alt` prop path in `images`
declarations — without it the accessibility rules cannot detect or fix
missing alt text.

## One pipeline, four consumers

Whatever you declare is honored by ONE compiler
(`compileDocumentAppearance`) feeding the editor canvas, the preview
route, production `<Render>` (via `AnvilKitRender`), and the HTML and
React exporters. If your component looks different in any of those
surfaces, that is a bug — file it; never fork a per-surface style
path.

## What does not change

- **Legacy components keep working.** A config with no
  `metadata.anvilkit.editor` simply gets no style targets — native
  Puck fields behave exactly as before.
- **Your own `metadata` is untouched.** The editor reads only
  `metadata.anvilkit.editor` and ignores everything else you store.
- **A malformed declaration is ignored, not fatal.** If `version` is
  not `"2"`, the whole block reads as absent and the component stays
  un-adopted.
